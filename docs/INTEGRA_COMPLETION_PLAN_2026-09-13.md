# Integra: план доведения до полного рабочего macOS-приложения

Основание: прямое поручение владельца 2026-09-13 и повторный аудит
`INTEGRA_AUDIT_REVIEW_2026-09-13.md`. Это план исполнения, не утверждение
готовности и не изменение Product Rules. Исторический READY_APP_V1 — baseline,
не синоним выполнения всего перечисленного ниже. Расширения не исключаются
из конечного результата только потому, что ранее были отложены.

## Что считается завершённой функцией

Для каждой функции обязательна запись: требование и тип источника → владелец
компонента → production entrypoint → действие native UI → зависимости →
реальные выходные файлы → автоматические проверки → smoke из конкретного
пакета → commit/manifest → ограничения. Отдельные статусы: backend, UI,
проверка пакета, установка пользователю. Нельзя заменять их одним PASS suite.
Неготовые действия disabled с точной подписью «В разработке».

Основной маршрут: источники → определение возможностей → «Что нужно получить?»
→ выбор результатов → автоматические зависимости → план → «Выполнить» →
реальная обработка → необходимая смысловая проверка → результаты и действия.
SeminarText, VideoText и BookText остаются внутренними pinned-компонентами.

проверяются и переиспользуются. Внутри блоков — ограниченные Issues/PR,
один владелец записи файла, независимый QA/review по риску.

## Цикл доставки

Текущее main/Issue → ограниченная ветка → implementation + regression →
governance validator + focused/full suite + macOS build/smoke → diff/review →
commit/push/PR → успешный CI и mergeability → безопасный merge → проверка main
→ известная обратимая установка с backup → проверка установленного пакета →
следующий блок. Существующие незакоммиченные изменения не теряются.

Один удачный runtime smoke не считается native UI smoke. Число тестов не
является критерием приёмки. Свидетельства фиксируются с датой и уровнем:
STATIC / UNIT / REAL_COMPONENT / BUNDLE / NATIVE_UI / INSTALLED.

## Уточнения и границы

Для начала P0 уточнения не нужны: scope и порядок определены фактами.
Работа для личного использования на macOS, без изменения source-репозиториев.
Не выполняются автоматически работа с новыми приватными данными/аккаунтами,
платежи, реальные социальные публикации, принятие знаний, уничтожение данных
или публичный release. Эти зависимости не маскируются заглушками и не
останавливают независимые технические блоки. Неизвестные API-возможности
проверяются перед реализацией; неподдерживаемое платформой не обещается.

# Аудит Integra относительно целей и задач

Дата: 2026-09-13. Аудит кода, установленного runtime, целей, GitHub и тестов.
Не является заявлением о полной готовности продукта или о качестве всех
пользовательских расшифровок.

## 1. Итог

Integra — работающее macOS-приложение с реальной обработкой медиа и документов,
но исходный продуктовый сценарий выполнен лишь частично:

`источники → обработка → темы → проверка → знания → навигация → публикация`.

Лучше всего реализованы загрузка отдельных источников, расшифровка, SRT,
базовые медиаоперации, документы и файловые результаты. Главные незакрытые
части — полноценный Knowledge Studio, расширенное редактирование тем,
мульти-источниковая работа и весь Media Studio. Исходные три приложения
не интегрированы во всей полноте своих работающих возможностей.

Старое утверждение «всё основное реализовано» было слишком широким:
готовность контракта/модуля/теста неоднократно смешивалась с готовностью
пользовательского сценария в установленном приложении.

## 4. Существенные несоответствия

1. **Roadmap не является точной матрицей runtime.** В `state/integra_state_v1.json`
   R9A/R9B/R9C и студии помечены ACCEPTED, но это не означает полный native UI.
   `docs/INTEGRA_PLAN.md` §18 всё ещё называет следующей стадией R10, хотя
   R10/R12/R13/R14 уже закрыты. Общий GitHub #1 описывает более широкий итог,
   чем принятый READY_APP_V1. Нужны раздельные статусы contract/runtime/UI/release.
2. **UI сам себе противоречит.** Review/Evidence/Knowledge в source-first registry
   недоступны, хотя часть последующих действий реализована в результатах.
   Это не основание включить все кнопки: нужно связать конкретные сценарии.
3. **В установленной версии сочетание topics+burn может пропустить burn.**
   В `user_media.run_job` после topics был преждевременный return. Исправление
   и регрессия есть в #129, но ещё не доставлены.
4. **Повторное использование результатов неполно.** Новые downstream-запуски
   через source-first часто снова входят в ASR. Нужен hash/model/config-bound
   reuse уже готовых SRT/Word Timeline, не повтор ради получения другого результата.
5. **Готовность контракта знаний была преувеличена.** V2-проверенные фрагменты,
   schema Concepts и проектный граф не равнозначны работающей базе знаний.
6. **Неполная автономность runtime.** Внешние модели/инструменты нужны после
   установки `.app`; current-Mac preflight не доказывает установку на чистом Mac.
7. **OCR provenance требует дальнейшего усиления.** Наличие локального файла
   модели не доказывает модель в повторно использованном Surya server. #129
   делает это ограничение явным. Полная region-навигация также отсутствует.
8. **Качество ASR не равно PASS тестов.** Нужен небольшой воспроизводимый набор
   реальных разрешённых записей с шумом, тишиной, повторами и длинными паузами.
   Старые ошибочные расшифровки не были автоматически заменены.

## 5. План дальнейших действий

Порядок: сначала завершить текущую доставку и надёжность, затем замкнуть
основной продуктовый путь, затем расширять студии. Проценты готовности и сроки
без оценки сложности не назначаются.

| Этап | Действия | Проверяемый критерий завершения |
|---|---|---|
| 0. Завершить #129 | Не смешивать с новыми фичами. Проверить новые три component-пути из одного готового `.app`, проверить UI, diff, commit→PR→CI→merge→установка с rollback | В установленном приложении работают machine Evidence, VideoText media, OCR page selection; 581+ тестов и bundle smoke; исходные проекты неизменны |
| 1. Единая правда о готовности | Сверить roadmap/state/registry/UI с этой таблицей; отделить контракт, production adapter, UI и доставленную версию | Ни одна функция не считается готовой только по документам; disabled-кнопки и причины соответствуют runtime |
| 2. Надёжная повторная обработка | Reuse готовых TXT/SRT/Word Timeline по хешам; единая отмена процессов; retry с checkpoints; тест комбинаций outputs; тесты ASR-артефактов | Запрос тем/перевода/клипа не запускает ненужную ASR; отмена не оставляет процессы и не даёт ложный COMPLETED |
| 3. Завершить темы и review | Детальность тем; RENAME/SPLIT/MERGE/DEFER; границы/цитаты/прослушивание; полный маршрут от machine Evidence | Пользователь проходит проверку внутри Integra; source-границы и исходные слова сохранены; никаких auto-accept решений |
| 4. Завершить Knowledge Studio | Согласовать V1/V2 фактические возможности; просмотр знаний/понятий/связей, provenance, переходы к словам и медиа | Source→Topics→Review→Knowledge→точная цитата/таймкод работает без ручного переноса файлов; неподдержанные случаи явные |
| 5. Проекты и несколько источников | Native copy-on-write import; corpus/collection; PDF/слайд↔видео; продолжение плейлиста через ASR/темы | Один проект объединяет несколько типов источников, с отдельной проверяемой lineage и без изменения оригиналов |
| 6. Довести Media Studio | Clip по теме/цитате; выбор скорости+SRT; blur/watermark; filler review/mute; TTS; реальный dereverb с preflight | Каждый пункт вызывает исходный VideoText, создаёт проверенный файл, управляется отменой и сохраняет provenance |
| 7. Довести BookText-интеграцию | DjVu, ordered image book, geometry/region navigation, иллюстрации/описания, точная идентичность OCR runtime | Реальные выбранные страницы и регионы совпадают с оригиналом; QA/PDF ошибки не скрываются; модели установлены/проверены |
| 8. Единый выпуск результатов | Удобные TXT/SRT перевода; единое формирование пакета; нужные DOCX/PDF; Obsidian/OneDrive из результатов | Пользователь получает читаемые файлы без разбора JSON; локальный OneDrive не называется cloud-confirmed |
| 9. Приёмочный кандидат | Матрица E2E на разрешённых реальных примерах; clean-Mac dependencies; interruption/offline/retry/rollback; инструкция | Весь согласованный основной сценарий пройден через UI; известные ограничения перечислены; ручная приёмка продукта отдельно от CI |
| 10. Отдельные расширения | Marketing, Learning, Assistant; затем social по отдельным задачам | Не тормозят завершение ядра; каждая новая функция имеет реальный backend, источники и собственные критерии качества |

План не требует спрашивать разрешение на каждый технический шаг. Но решения
о принятии знаний, реальная внешняя публикация, доступ к новым аккаунтам,
разрушительные изменения и публичный release не подменяются автоматизацией.

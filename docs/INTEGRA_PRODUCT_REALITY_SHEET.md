# INTEGRA PRODUCT REALITY SHEET — FACTS ONLY

## 1. DECLARED END PRODUCT

Срез: 2026-09-22; проверенный GitHub `main`: `2af7de54964d267ff47267f9e43bb9c0b41973ac`. Это factual snapshot, не изменение Product Definition, roadmap, приоритетов или acceptance. Новые builds/tests не выполнялись.

**Заявленная цель:** native macOS Integra объединяет обработку источников, transcript/document evidence, Topics, human review, canonical knowledge/media, cross-navigation, Obsidian export и OneDrive publication. Результаты сохраняют связь с исходным временем/словом/страницей/слайдом/областью и revision. Standalone-продукты и исходные пользовательские данные сохраняются. [Product Definition][pd], [Plan §§1, 3–4, 13, 16][plan].

Границы заявленного продукта в источниках:

- **Sources:** local video/audio; YouTube video/playlist; PDF, PPTX, DOCX, TXT, Markdown, images/scans/supporting materials перечислены в Plan. Однако live YouTube/download и bound local OCR engine отложены в Product Definition. Единый обязательный перечень *полностью выполняемых* source journeys после MCWMA — `UNDEFINED`; регистрация источника не равна его полной обработке.
- **Outputs/capabilities:** Transcript, translation, SRT/Word Timeline, Topics, review, Canonical Evidence/Knowledge, media, provenance/navigation, managed Obsidian/OneDrive publication заявлены в Plan. General standalone DOCX/PDF/SRT/audio/video export, automatic multi-source matching и representative full Media Studio execution отложены. Общий экспорт SRT и SRT внутри принятого primary journey — разные границы. Marketing/Learning/Assistant/social и другие deferred capabilities не объявлены готовыми. [pd][pd], [Plan §§4, 16][plan].
- **GUI:** buildable, launchable, usable native `.app`; source-first selection, output/dependency planning, background execution, конкретные доступные результаты, Operations & Diagnostics; unavailable capabilities должны честно показываться как «В разработке». [pd][pd].
- **Recovery/restart/persistence:** project history/lifecycle, persisted results, checkpoints, pause/resume, cancel, bounded retries, child-process termination, backup, crash recovery и verified resume после возвращения external workspace заявлены. Recovery #161 отдельно требует failure/timeout/cancel/stale RUNNING/orphan cleanup/reuse/invalidation/subsequent success. Это требования, не подтверждение их полного пользовательского выполнения. [Plan §§4.1, 12–13, 16][plan], [Recovery direction][recovery].
- **Установка и обычный запуск:** local reproducible `.app` и выполнение journey на reference Mac обязательны. Packaging document задаёт minimum macOS 13, local ad-hoc seal и precondition `/usr/bin/python3`; штатный GUI launch принят для конкретного Candidate #156. Полный пользовательский процесс установки на неподготовленный Mac — `UNDEFINED`. [Packaging][pack], [owner #156][accepted].
- **Runtime/model dependencies:** текущие execution/build paths используют SeminarText/VideoText/BookText, FFmpeg/ffprobe, Whisper/model/VAD, Ollama (принятые Topics: `gemma3:4b`), WhisperX/Russian alignment model и Python, включая external Python 3.13 для alignment. Они не все являются самодостаточной частью `.app`. Reference Mac задан: MacBook Air M5, 16 GB RAM, 512 GB SSD; Plan прямо не называет его окончательным minimum hardware requirement. Пользовательская ответственность за установку/обновление зависимостей и окончательные минимальные hardware requirements — `UNDEFINED`. [Build][build], [ASR runtime][asr], [Word runtime][word], [Ollama runtime][ollama], [Plan §12][plan].
- **Без Terminal/Codex:** native GUI journey определён и принят; отдельное end-to-end требование «установка, обслуживание, recovery и обычная работа без Terminal/Codex» в рассмотренных источниках — `UNDEFINED`. Это не утверждение, что Terminal нужен для каждого запуска.
- **Packaging/signing/notarization/distribution:** local package обязателен; public signing/notarization/distribution/update publication явно deferred и не следуют из READY_APP_V1 acceptance. Для public 1.0 Plan требует отдельную verification signing, licensing, update/rollback и backup. [pd][pd], [Packaging][pack], [Plan §§14, 16][plan].
- **Готовность всего приложения:** исторический критерий READY_APP_V1 определён в Product Definition и Plan §16: core + safe publication + native journey + packaging/compatibility/recovery + explicit owner R14. #151 задаёт более узкий MCWMA; #157 прямо не считает его завершением долгосрочного продукта. Согласованное применение этих границ к нынешнему «полностью работающему приложению» — `UNDEFINED`. [Strategy #151][strategy], [Checkpoint #157][checkpoint].

## 3. AMBIGUITIES / CONTRADICTIONS

1. **Несогласованные current-state описания.** Plan §18 называет текущей границей R9C и следующим R10; [roadmap][roadmap]/[state][state] помечают цепочку до R14 accepted; CURRENT v2 фиксирует только #156 primary journey. Историческая [owner R14 acceptance][r14] реальна, но карта применимости её более широкой приёмки к нынешнему приложению отсутствует. Закрытие milestone этого не разрешает.
2. **Граница PRODUCT DONE.** READY_APP_V1 включает Knowledge/media/publication; MCWMA принимает один primary journey; #157 предлагает дальнейший небольшой набор и одновременно сохраняет broader Product Definition. Предложение #157 не доказывает, что broader scope отменён. Однозначный актуальный обязательный конечный набор — `UNDEFINED`.
3. **Source/output depth.** Plan требует YouTube, документы и multi-source, тогда как Product Definition откладывает live download, local OCR и automatic matching/full media execution. Не определено, какой пользовательский результат по каждому из этих источников обязателен для PRODUCT DONE: source registry/contract нельзя считать фактическим выполнением pipeline. Исчерпывающая current source × output граница — `UNDEFINED`.
4. **Условия самостоятельного использования.** Technical runtime identities и local packaging описаны, но единый end-user setup/dependency lifecycle, окончательный minimum hardware и граница работы без Terminal/Codex — `UNDEFINED`. #156 не является clean-machine installation acceptance. Signing/public distribution, напротив, явно отложены, а не «забыты».
5. **Пределы подтверждённой повседневной надёжности.** Recovery/persistence требования существуют; принятие одного persisted primary run не доказывает restart/resume, многократную работу, перенос/backup/restore и все ошибки. Recovery #161 остаётся отдельной незавершённой работой; актуальное полное owner evidence для этих результатов отсутствует. Здесь не меняются его scope или gates.
